# Cella Playground

> **一個會說出自己驗了什麼的證明語言。**

來玩：https://timcsy.github.io/cella-playground/

不用安裝，瀏覽器打開就能寫、檢查、執行。

---

## 「通過」裡面混著什麼？

大多數證明系統檢查完只告訴你一件事：通過，或沒通過。

可是「通過」裡常常混著不同的東西：真的驗過的、某一步被塞了佔位而沒人再看的、某個假設被默默接受的、某一塊根本還沒寫的。一個布林裝不下這些區別，區別就消失了。

Cella 的產出不是布林，是**判決**：

- **Accept**：驗過了，並且列出**在什麼假設下**（例如「這個函式假設會終止」「這是公理」）。
- **Reject**：哪裡錯、錯在哪一條規則（宇宙層級、型別不合、覆蓋不全、終止性……）。
- **Unknown**：沒辦法下結論，並說出理由——例如「這裡還有一個洞」「它依賴的定義還沒驗完」。Unknown 會沿著依賴往外傳，不會被偷偷算成通過。

每一次檢查由兩個各自獨立寫成的檢查器把關（一個 kernel，一個從零重寫、不依賴 kernel 的 checker）；兩者不一致時大聲失敗。在瀏覽器裡沒有跑到第二個檢查器時，判決會明說「未經第二個 kernel 重驗」。

## 可以在這裡做什麼

- **寫程式，也寫證明**：依值型別，寫程式和證明定理是同一件事。
- **帶著洞寫**：寫 `_` 或 `?名字`，判決是 Unknown，並告訴你那個洞需要什麼型別。
- **看見目前的狀態**：游標停在 `by { … }` 裡會顯示還要證明的目標；滑鼠停在名字上會顯示它的型別。
- **把等式當成路徑**：Cella 建立在 Cubical Type Theory 上。兩個型別等價時，`ua` 給出它們之間的路徑，沿著路徑 `transport` 會真的算出結果——與 Cubical Agda 同一套理論。
- **用 tactic**：`simp`、`induction`、`ring`、`omega` 等，也可以自己定義 tactic。
- **執行**：程式在瀏覽器裡編成 WebAssembly 直接跑，包含 IO。

## 從哪裡開始

三條路線，選適合你的：

| | 路線 | 適合誰 | 你會體驗到 |
|--|------|--------|-----------|
| 🌱 | **初心者** | 沒學過數學 | 用生活的例子理解「程式就是證明」 |
| 🔬 | **數學人** | 學過數學 | 從古典數學走到同倫型別論 |
| ⚡ | **老手** | 用過 Lean 4／Agda／Coq | 判決三態、cubical 的計算、與它們的差別 |

另外有 18 個範例可以直接打開：自然數、串列、字串、IO、路徑、transport、`ua`、tactic、type class 等。

## 和其他系統比較

| | Lean 4 | Cubical Agda | Coq | **Cella** |
|---|-------|-------------|-----|-----------|
| 等式（路徑）可計算、`ua` 可執行 | ✗ | ✓ | ✗ | **✓** |
| 在瀏覽器裡原生檢查與執行 | ✗ | ✗ | △（jsCoq） | **✓** |
| 判決說得出驗了什麼（Accept／Reject／Unknown ＋ 假設） | ✗ | ✗ | ✗ | **✓** |
| 兩個獨立的檢查器互相印證 | △（外部重驗器） | ✗ | △（外部重驗器） | **✓** |

cubical 的那一列，Cella 與 Cubical Agda 做的是同一件事：讓等價成為相等，而且這個相等可以計算。Cella 另外在意的，是說清楚每一次「通過」靠的是什麼。

## 現況

Cella 是實驗中的語言，還在變動：語法、標準庫、快照格式都可能改。發現怪事（該拒絕的被接受、該接受的被拒絕），那正是我們想知道的。
